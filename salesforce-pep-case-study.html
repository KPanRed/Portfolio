01 — System Architecture

Understanding Platform Complexity

The wealth management platform is not a monolithic application—it's a complex system of interconnected modules, each serving different workflow needs while sharing common data structures, user populations, and business logic. Financial Advisors and Client Service Teams navigate this ecosystem differently, accessing different interfaces and workflows depending on their role.

This creates a systems design challenge: How do we measure and improve user experience across a distributed architecture where performance in one module affects perception of the entire system?

Six Interconnected System Modules
Activities → Homepage → Relationship Groups → Contact Management → Financial Accounts → Overall Platform Experience. Each module represents a distinct interface with its own workflows, yet all share the same users, data layer, and design system. Performance gaps in one module create ripple effects across the entire user experience.

02 — System Performance Baseline

Measuring the Entire Ecosystem

In complex systems, individual module performance matters less than the aggregate experience. Users don't think "the Homepage module scored 4.1"—they think "this platform feels slow and cumbersome." The overall system score provides a baseline for understanding whether the architecture as a whole is meeting user needs.

This isn't a feature problem; it's a systems architecture problem. The platform's design patterns, interaction models, and information architecture feel dated compared to modern systems.

04 — User Segment Analysis

One System, Two Distinct User Journeys

A critical systems design question: Can a single platform architecture serve two user populations with fundamentally different workflows? Financial Advisors are mobile, client-facing, and context-switching constantly. Client Service Teams operate from fixed workstations, managing administrative workflows with consistent tooling. The same system modules serve both—but the experience diverges dramatically.

The Architecture Serves One User Better Than the Other
CSTs rate the system at 4.55 overall, while FAs rate it at 3.70—a 0.85-point gap. This isn't a training issue or a preference issue. It's a systems architecture mismatch. The platform's design assumptions—stable connectivity, desktop-first interfaces, keyboard-heavy workflows—align with CST needs but create friction for FAs working in dynamic, mobile contexts.

Systems Design Implication
This performance gap reveals an architectural trade-off: the system was optimized for desk-bound, administrative workflows (CSTs) at the expense of mobile, client-facing workflows (FAs). Fixing this requires more than UI tweaks—it demands architectural decisions about offline capability, mobile-first design patterns, and context-aware interfaces that adapt to where and how FAs work.
05 — Decomposing System Failures

From User Complaints to Architectural Patterns

Qualitative feedback reveals systemic patterns—not isolated bugs, but recurring architectural decisions that create friction across multiple modules. By synthesizing 233 open-ended responses, we can map which design patterns are failing and why. This isn't a feature request list; it's a diagnostic map of system-level failures.

Three Categories of System Failure
1. Search Architecture — Users expect unified, exhaustive search, but the system returns partial results based on recency, not relevance.

2. Workflow Orchestration — Multi-step processes (scheduling, network management) require excessive clicks and lack intelligent defaults.

3. Information Architecture — Critical data (CUSIPs, network contacts) is buried or requires obscure knowledge to access.

06 — Homepage: Search

Search Does Not Meet User Expectations

01

Search Does Not Cover All Entities

Users expect a unified and exhaustive search across all entities, but the current system only returns partial or recent results, severely limiting discoverability.

"When searching for a client, profile, contact or prospect, it does not search ALL."
"It does not necessarily search 'all clients'… should provide ALL Smiths."
"Fix the search function! Typing in Smith brings up the last 5 accessed accounts."
02

Default Search Filter Adds Friction

The default search setting does not align with user workflows, forcing repetitive manual adjustments and reducing efficiency.

"Search: All - I need to set to default to Search: Profile. Current default 'All' requires dozens of extra clicks."
03

Search Results Are Inconsistent

Search behavior is unpredictable, returning varying types of results without clear logic, which confuses users and undermines trust in the system.

"Sometimes it shows the last person I searched for… sometimes the Relationship Group… sometimes just the address."
07 — Homepage: Get a Quote

Quote Tool Requires Obscure Knowledge

Unusable Without Ticker or CUSIP
Users must know the exact ticker symbol or CUSIP to retrieve a quote. CUSIPs are difficult to find and not centralized, making the feature nearly unusable for many. There is no support for searching by company name, and the lack of autocomplete forces users to switch screens or rely on external tools.
Opportunity
Add company name search with autocomplete and ticker/CUSIP suggestions. Allow users to search "Apple" and see "AAPL (NASDAQ)" as a suggestion—matching how external financial tools work.
08 — Homepage: Calendar

Calendar Lacks Weekend Awareness

01

No Weekend Logic in To-Do System

The system fails to recognize weekend workflows, requiring manual effort from users to manage weekend tasks—something the previous system handled more intuitively.

"I hate that I have to remind myself every Friday to check Saturday and Sunday to-dos because the system can't tell it's a weekend (the old system wasn't like this)."
09 — Activities: Appointments

Scheduling Friction & Missing Features

01

Description Field Should Be Optional

Mandatory fields that aren't always relevant create friction and slow down scheduling workflows.

"The description field in the appointment should not be mandatory, as it is not always necessary."
02

Limitations in Multi-Client Scheduling

The current system lacks flexibility for group scheduling, which is essential for users managing families or client groups.

"When scheduling appointments, users can only invite one client at a time. They want the ability to schedule with multiple clients simultaneously and send them individual email and text notifications."
03

Need for Text Reminders

Text reminders are critical for improving client attendance and reducing no-shows, especially for virtual meetings.

"Users want the ability to send text reminders to clients when scheduling an appointment."
"Users need the option to send text message reminders for Zoom appointments."
04

No Visibility into Sent Reminders

Users need visibility into communication history to confirm delivery and troubleshoot missed appointments.

"Why can't we not see if a reminder text or email was sent to a client the day before?"
05

Lack of Email Preview Before Sending

Users need control and confidence in client communications—previewing messages helps prevent errors and miscommunication.

"Before sending an email confirmation, users would like to preview the message to ensure accuracy before it reaches the client."
06

Need for Split-Screen View (Multi-FA Users)

Users managing multiple financial advisors need a more efficient layout to view and coordinate across teams.

"For users who work with multiple FAs, a split-screen view showing appointments and tasks for each FA would be helpful."
10 — Relationship Group

Network Management is Too Complex

01

Updating Network Is Cumbersome

Users struggle to add professional contacts like CPAs and attorneys due to a multi-step, unintuitive process. The inability to create profiles directly from the update network view adds complexity.

"CPA's and other COI's (circle of influence) are not easily entered and linked to clients – we like to have the COI's right at the top in the client relationship profile page for ease and efficiency. Gets too buried the SF way."
"Adding a CPA or attorney as part of the client's network is exceptionally difficult. We gave up and just add the CPA & Attorney info to the Relationship notes."
02

Life Events & Network Features Are Underused

The complexity of entering life events and network members discourages usage. Redundant data entry and unclear workflows reduce adoption of these features.

"Adding network members and life events is very confusing. Having to add the same life event multiple times (for each spouse or each member of the relationship group) is a pain. I do not use these features as often as I should due to the complexity of entering."
Impact
Users are abandoning intended features (network connections, life events) and reverting to freeform notes fields as workarounds. This defeats the purpose of structured data and limits the platform's ability to surface insights or automate workflows.
